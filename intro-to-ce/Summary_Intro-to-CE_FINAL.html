Public Key

ตั้งค่า 3 ขั้น

1. ssh-keygen -t ed25519          # สร้างคู่กุญแจบน Client (ได้ไฟล์ใน ~/.ssh/)
2. คัดลอกเนื้อหา id_ed25519.pub ไปใส่ ~/.ssh/authorized_keys บน Server
3. logout แล้ว ssh ใหม่               # เข้าได้โดยไม่ถาม password
# ระบุ key เอง: ssh -i /path/to/private_key debian@IP

4 · Windows: ACL (Access Control List)

แทนที่จะมีแค่ u/g/o ตายตัว Windows ให้แต่ละไฟล์/โฟลเดอร์มี รายการสิทธิ์ ของตัวเอง ละเอียดกว่า

มี →
ACLAccess Control List
ประกอบด้วย →

ACE 2group 1 · Allow · Modify

ACE (Access Control Entry) = 1 บรรทัดในรายการ ระบุว่า ใคร (user/group) + Allow หรือ Deny + สิทธิ์อะไร

กฎสำคัญ

Deny สูงกว่า Allow ถ้ามีทั้งสองอย่างขัดกัน Deny ชนะ

รวมสิทธิ์จากหลาย group ถ้า user อยู่หลายกลุ่ม สิทธิ์ Allow จะรวมกัน

Inheritance ไฟล์/โฟลเดอร์ย่อยรับ ACL มาจากโฟลเดอร์แม่โดยค่าเริ่มต้น เปลี่ยนได้

ระดับสิทธิ์ (จากน้อยไปมาก)

Read → Write → Modify → Full control

Full control = ทำได้ทุกอย่าง รวมถึงเปลี่ยน permission และเปลี่ยน owner

ตัวอย่างโจทย์

Group A: Allow Modify · User A (อยู่ใน Group A): Allow Read + Deny Write

ผล: User A อ่านได้ แต่ เขียนไม่ได้ เพราะ Deny Write ชนะ Allow Modify ที่ได้จากกลุ่ม

8 · Authentication กับ GitHub

ตอน push / pull กับ remote ที่เป็น private หรือแก้ไขได้ GitHub ต้องรู้ว่าเราเป็นใคร

วิธี ① HTTPS URL

ใช้ URL แบบ https://github.com/user/repo.git ครั้งแรกจะถาม username และ Personal Access Token (PAT)

PAT ใช้แทน password (GitHub ไม่รับ password ธรรมดาสำหรับ Git แล้ว) สร้างได้จากหน้า Settings บนเว็บ กำหนดสิทธิ์และวันหมดอายุได้

วิธี ② SSH

ใช้ URL แบบ git@github.com:user/repo.git สร้างคู่กุญแจ แล้วเอา Public Key ไปใส่ใน GitHub (หลักการเดียวกับ SSH เข้า VM)

เครื่องส่วนตัวเก็บ Private Key ไว้ ไม่ต้องกรอกอะไรทุกครั้ง

Credential manager (จำ token ไว้ ไม่ต้องกรอกซ้ำ)

ระบบที่เก็บ

ครั้งแรกกรอก username + PAT แล้วระบบจะเก็บไว้ ครั้งต่อไปไม่ถามอีก

สรุปไว้ทวนก่อนสอบ

OS ทำไมต้องมีเป็นตัวกลางจัดการทรัพยากร (CPU, RAM, storage, I/O) ให้หลาย App ใช้พร้อมกันได้โดยไม่ชนกัน และควบคุมสิทธิ์/ความปลอดภัย
Permission POSIX กับ ACL ต่างกันอย่างไรPOSIX มี 3 กลุ่ม (owner/group/others) × 3 สิทธิ์ (r/w/x) ส่วน ACL เป็นรายการ ACE ที่ระบุ user/group รายตัวได้ มี Allow/Deny และ Deny ชนะ Allow
chmod 664 คืออะไรrw-rw-r-- (owner และ group อ่าน/เขียนได้ others อ่านได้อย่างเดียว)
Git ต่างจาก GitHubGit = เครื่องมือ version control ในเครื่อง · GitHub = บริการ cloud เก็บ remote repo พร้อมเครื่องมือทำงานทีม (pull request, issue, code review)
push กับ pullpush = ส่ง commit จาก local ขึ้น remote · pull = ดึงอัปเดตจาก remote ลง local
Pull request ใช้ทำอะไรแจ้งทีมว่ามีการแก้ไขใน branch อยากให้ตรวจ (code review) แล้ว merge เข้า main
